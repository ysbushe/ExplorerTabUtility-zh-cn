# 标题栏/标签栏双击关闭当前页设计记录

## 结论

本阶段不实现“资源管理器标题栏/标签栏双击关闭当前页”功能。

原因是当前代码虽然可以通过低级鼠标 Hook 获取点击坐标，也可以识别资源管理器文件列表空白处，但尚不能稳定区分 Windows 11 资源管理器的标签栏、普通标题栏、地址栏、搜索框和文件列表区域。

如果在命中测试不可靠的情况下拦截双击，可能破坏 Windows 原生标题栏双击最大化/还原，或导致误关标签页。

## 当前源码能力

- `Hooks/Mouse.cs`：可获取鼠标坐标、判断双击、识别已配置的鼠标 Profile。
- `Helpers/Helper.cs`：已有 `IsExplorerEmptySpace()`，用于保守识别文件列表空白处。
- `Hooks/ExplorerWatcher.cs`：内部存在对当前标签发送关闭命令的用法，但依赖未公开命令值，适合继续封装前先实机验证。

## 后续如需实现

建议仅实现“标签栏明确区域双击关闭当前标签”，不要实现“标题栏任意位置双击关闭”。

最低要求：

- 新增高级设置项，默认关闭。
- 鼠标 Hook 仅在设置开启后启用相关判断。
- 必须可靠排除普通标题栏、地址栏、搜索框、文件列表空白处和导航栏。
- 关闭前确认当前窗口有多个标签页；最后一个标签页不应被误关。
- 不影响“空白处双击返回上级”和普通鼠标 Profile。
- 对 Windows 11 不同版本、缩放比例、主题和多窗口多标签场景做实机验证。
